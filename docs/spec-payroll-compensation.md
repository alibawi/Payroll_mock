# Spec — الموديول 2: تعويض الموظف (Employee Compensation)

> **المصدر**: الدراسة الأقسام 2 (الفجوة 1)، 3.3، 4.5، 5.1، 6، 8.2 (كيان 5 + «قرار نمذجة»)، 8.6، 10 (Phase 2)، 11 (قرارات 2، 11).
> **الجوهري**: مبلغ الراتب **لا يُوضع على `Employee`** — يبقى بسجل `EmployeeCompensation` المؤرّخ (حفاظاً على التاريخ والـ proration وسطر تدقيق نظيف).

---

## 1. النطاق وصلته بالموديولات
- يربط **الموظف** (من HR — Placeholder JSON) بـ **الملف** (`ProfileId`) و**هيكل الراتب** و**درجة/مرحلة السلّم** (حكومي) أو **الأجر الأساسي** (خاص).
- **الملف على مستوى التعويض لا المنشأة** (قرار #2): نفس المنشأة تشغّل النظامين (دائمون حكوميون + عقود/خاص)، وموظفو العقود قد يخضعون للضمان بدل التقاعد (4.5).
- يعتمد على: الموديول 1 (Profiles/Structures/GradeScale/Components).
- يغذّي: الموديول 5 (المحرك يقرأ التعويض النافذ بتاريخ الفترة).

## 2. نموذج البيانات

### 2.1 `EmployeeCompensation` (`payroll/compensations.json`)
| الحقل | ملاحظات |
|---|---|
| `id`, `employeeId` | ربط بموظف HR |
| `profileId`, `salaryStructureId` | |
| `effectiveFrom`, `effectiveTo?` | سجل تاريخي؛ الحالي `effectiveTo = null` |
| `currencyCode` | IQD |
| `paymentMethod` | `Bank` \| `Cash` |
| `bankAccountNo?` | مطلوب عند Bank |
| `costCenterId?`, `projectId?` | تظهر بالقيد المحاسبي |
| `gradeStepId?` | حكومي: يشتق الاسمي والعلاوة |
| `baseSalary?` | خاص: الأجر الأساسي التعاقدي |
| `taxMaritalStatus`, `eligibleChildrenCount` | حقول مستقلة مع افتراض من `Employee` (قرار #11) |
| `isPensionExempt?` | استثناء من التقاعد/الضمان |
| `changeReason?`, `createdBy` | **قرار موك أب** (لأجل الـ Audit: ترفيع، علاوة، تعديل عقد…) |

### 2.2 `EmployeeCompensationComponent` (تجاوزات الموظف)
`compensationId, componentId, amount?, percent?` — مثل: بدل سكن تعاقدي 200,000، مخصصات منصب فعلية 150,000.

### 2.3 مشتقّات معروضة (غير مخزّنة)
الراتب الإجمالي المتوقع (Gross preview) = يُحسب بنفس `lib/payroll/engine.ts` على شهر كامل بلا حضور (**معاينة الراتب**)، الاسمي/العلاوة من الخلية، وعدد سنوات الخدمة.

## 3. دورة حياة الحالات
لا State Machine. الحالة المشتقة لكل سجل: **Upcoming** (`effectiveFrom` بالمستقبل) · **Current** · **Superseded** (`effectiveTo` مغلق). إنشاء سجل جديد يغلق الحالي تلقائياً (`effectiveTo = effectiveFrom − يوم`).

## 4. قواعد العمل
| # | القاعدة | المصدر |
|---|---|---|
| E-1 | لكل موظف سجل نافذ واحد بأي تاريخ (لا تداخل بالتواريخ) | 8.2 |
| E-2 | الموظف الحكومي: `gradeStepId` إلزامي و`baseSalary` ممنوع؛ الخاص: العكس | 6 |
| E-3 | الخاص: `baseSalary ≥ الحد الأدنى للأجور` (توضيحياً **350,000 د.ع**) قابل للضبط بإعدادات الموديول | 5.1 |
| E-4 | `paymentMethod = Bank` تتطلب `bankAccountNo` | 8.2 |
| E-5 | تجاوز مكوّن (override) يجب أن يكون المكوّن ضمن هيكل الراتب أو Allowance نشط | 8.2 |
| E-6 | ملف الموظف والأنظمة المفعّلة: لا تقاعد + ضمان معاً | 4.5 |
| E-7 | `eligibleChildrenCount ≥ 0`، و`taxMaritalStatus ∈ {Single, Married, …}` بافتراض من الموظف مع إمكانية التغيير | قرار #11 |
| E-8 | تغيير الراتب خلال الشهر ⇒ المحرك يعمل proration بتقسيم الفترة على السجلّين | 3.3 |
| E-9 | العلاوة السنوية (حكومي): زر «تطبيق علاوة» ينقل المرحلة +1 بسجل جديد ويضيف `annualIncrementAmount` **(قرار موك أب: أداة مساعدة)** | 4.2 |
| E-10 | الترفيع: انتقال لدرجة أعلى — بسجل جديد بنفس الآلية **(قرار موك أب)** | 4.2 |
| E-11 | لا حذف لسجل استُخدم بدورة رواتب (Posted/Paid) | مشتق |

## 6. مؤشرات (KPIs)
عدد الموظفين ذوي راتب معيَّن / بلا تعويض (تنبيه) · توزيع حكومي/خاص · متوسط الراتب الإجمالي لكل ملف · عدد التعديلات آخر 30 يوم · موظفون دون الحد الأدنى للأجور (تنبيه).

## 7. التكاملات (Placeholders)
- **HR**: قراءة لقطة الموظف عبر `IEmployeePayrollSnapshotProvider` (الدراسة 8.5) ← تُحاكى بـ `GET /api/payroll/hr/employees` من `mock-data/hr/employees.json`؛ الدراسة تعترف أن HR ما يكشف هذي العقود بعد.
- **استيراد Excel** للرواتب الحالية (Phase 2): زر رفع وهمي → معاينة أعمدة → تأكيد → يظهر شريط تقدّم ونتيجة (نجاح/أخطاء) **بدون معالجة حقيقية للملف**.
- تبويب «الراتب» داخل صفحة الموظف (بـ HR) ← رابط لشاشتنا.

## 8. قائمة الشاشات الكاملة
| # | الشاشة | المسار | ملاحظات |
